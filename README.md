# เฝ้าไฟ — ระบบแจ้งเตือนไฟเปิดทิ้งไว้ในห้อง (แจ้งลูกค้าผ่าน LINE OA)

เว็บแอปสำหรับเฝ้าดูสถานะไฟแต่ละห้อง ถ้าห้องไหนเปิดไฟทิ้งไว้นานเกินกำหนด ระบบจะส่งข้อความ
แจ้งเตือนไปยังลูกค้าของห้องนั้นโดยอัตโนมัติผ่าน **LINE Official Account**

## มีอะไรให้บ้าง

- แดชบอร์ดเว็บ แสดงสถานะไฟแต่ละห้องแบบเรียลไทม์ (อัปเดตทุก 5 วินาที) พร้อมตัวจับเวลาว่าเปิดมานานแค่ไหน
- ตั้งเกณฑ์ได้เองว่า "เปิดทิ้งไว้เกินกี่นาทีถึงแจ้งเตือน" และ "แจ้งซ้ำทุกกี่นาที"
- ส่งข้อความแจ้งลูกค้าผ่าน LINE Messaging API (push message) อัตโนมัติ
- หน้าลงทะเบียนผ่าน LIFF — ลูกค้ากดลิงก์เดียวในแอป LINE แล้วผูกบัญชีกับห้องได้เอง
- มี API ให้เซ็นเซอร์ไฟ/อุปกรณ์ IoT จริงยิงสถานะเข้ามาได้ (`POST /api/sensor/:roomId`)
- มีปุ่ม "เปิดไฟ/ปิดไฟ (จำลอง)" ในหน้าเว็บ ไว้ทดสอบระบบโดยยังไม่ต้องมีเซ็นเซอร์จริง
- ข้อมูลเก็บใน **MongoDB Atlas** (ฟรี ไม่หมดอายุ) ไม่หายตอน deploy ใหม่บนโฮสติ้งฟรี

## ภาพรวมการใช้งานจริงแบบไม่เสียเงิน

แผนที่ใช้ในคู่มือนี้: เก็บโค้ดไว้บน **GitHub** (ฟรี) → รันเว็บบน **Render** (ฟรี) → เก็บข้อมูลบน **MongoDB Atlas** (ฟรี)

> ⚠️ **ข้อจำกัดของแผนฟรีนี้:** Render จะ "พักเครื่อง" เว็บถ้าไม่มีคนเข้าใช้นาน 15 นาที พอมีคนเข้าใหม่จะใช้เวลาปลุกเครื่อง ~30-60 วินาที
> และในช่วงที่เว็บพักเครื่องอยู่ ตัวเช็ก "ไฟเปิดทิ้งไว้นานแค่ไหน" จะไม่ทำงานจนกว่าจะมีคนเข้าเว็บอีกครั้ง
> **วิธีลดปัญหานี้ง่าย ๆ:** เปิดหน้าแดชบอร์ดทิ้งไว้ในเบราว์เซอร์ตลอดเวลา (เช่น เปิดแท็บไว้ที่คอมร้าน) เพราะหน้าเว็บเรียก API ทุก 5 วินาทีอยู่แล้ว ทำให้เว็บไม่หลับ
> ถ้าต้องการให้แจ้งเตือนไวและแน่นอนเสมอแม้ไม่มีใครเปิดหน้าเว็บเลย ให้อัปเกรด Render เป็นแผน Starter ($7/เดือน) ซึ่งจะไม่มีการพักเครื่อง

## ขั้นที่ 1: ตั้งค่าฐานข้อมูล (MongoDB Atlas — ฟรีตลอดไป)

1. ไปที่ **https://www.mongodb.com/cloud/atlas/register** สมัครฟรี (สมัครด้วย Google ก็ได้ ไม่ต้องผูกบัตร)
2. ตอนถูกถามให้สร้าง cluster เลือก **M0 (Free)**
3. เลือก Cloud Provider/Region อะไรก็ได้ (เลือกที่ใกล้ เช่น Singapore) → กด **Create**
4. ระบบจะถามให้สร้าง **Database User** — ตั้ง username/password (เก็บไว้ดี ๆ จะใช้ในขั้นต่อไป)
5. หัวข้อ **Network Access** (หรือ "Where would you like to connect from?") → เลือก **Allow access from anywhere** (จะได้ IP `0.0.0.0/0`) — จำเป็นเพราะ Render ใช้ IP ที่เปลี่ยนได้
6. รอ cluster สร้างเสร็จ (1-3 นาที) → กดปุ่ม **Connect** → เลือก **Drivers** → เลือก Node.js
7. จะได้ connection string หน้าตาแบบนี้:
   ```
   mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   แทนที่ `<username>` และ `<password>` ด้วยค่าที่ตั้งไว้ในขั้นตอนที่ 4 → **เก็บ string นี้ไว้** จะใช้ตอนตั้งค่าบน Render

## ขั้นที่ 2: เอาโค้ดขึ้น GitHub

1. ถ้ายังไม่มีบัญชี ไปสมัครฟรีที่ **https://github.com/signup**
2. เปิดโฟลเดอร์โปรเจกต์ใน VS Code (ถ้ายังไม่เปิด)
3. ไปที่แท็บ **Source Control** ทางซ้าย (ไอคอนเหมือนกิ่งก้าน) → กดปุ่ม **"Publish to GitHub"**
4. ถ้าเป็นครั้งแรก VS Code จะให้ login GitHub ก่อน → ทำตามขั้นตอน
5. เลือก **"Publish to GitHub private repository"** (แนะนำให้เป็น private เพราะมีโค้ดระบบลูกค้า) → ตั้งชื่อ repo เช่น `line-light-notify` → กด OK
6. รอสักครู่ โค้ดจะถูกอัปขึ้น GitHub ให้อัตโนมัติ

## ขั้นที่ 3: Deploy เว็บบน Render (ฟรี)

1. ไปที่ **https://render.com** กด **Get Started** → สมัครด้วยบัญชี **GitHub** (ง่ายสุด ไม่ต้องผูกบัตร)
2. ที่หน้า Dashboard กด **New** → **Web Service**
3. เลือก **Connect** repo `line-light-notify` ที่อัปไว้ในขั้นที่ 2 (ถ้าไม่เห็น ให้กด "Configure account" เพื่ออนุญาตให้ Render เข้าถึง repo นั้น)
4. ตั้งค่า:
   - Name: ตั้งอะไรก็ได้ เช่น `line-light-notify`
   - Region: เลือกที่ใกล้ เช่น Singapore
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: **Free**
5. เลื่อนลงหา **Environment Variables** → กด **Add Environment Variable** เพิ่ม 2 ตัว:
   - `MONGODB_URI` = connection string จากขั้นที่ 1 (อย่าลืมเติม username/password ที่แท้จริง)
   - `SENSOR_API_KEY` = ตั้งรหัสลับอะไรก็ได้ (ใช้ตอนเชื่อมเซ็นเซอร์ไฟจริง)
6. กด **Create Web Service** → รอ build เสร็จ (2-5 นาที)
7. เสร็จแล้วจะได้ URL ถาวรหน้าตาแบบ `https://line-light-notify-xxxx.onrender.com` ← **นี่คือโดเมนของคุณ** ใช้แทนที่ "โดเมนของคุณ" ในทุกขั้นตอนถัดไปนี้

> หลังจากนี้ ทุกครั้งที่คุณแก้โค้ดแล้ว push ขึ้น GitHub ใหม่ (กด commit + push ผ่าน Source Control ใน VS Code) Render จะ deploy โค้ดใหม่ให้อัตโนมัติ — ข้อมูลห้อง/ลูกค้าจะไม่หาย เพราะเก็บอยู่ใน MongoDB ไม่ได้เก็บในตัวเว็บ

## ตั้งค่า LINE ในตัวระบบ

1. เปิด URL ของ Render ที่ได้มา (เช่น `https://line-light-notify-xxxx.onrender.com`) — ครั้งแรกอาจรอ 30-60 วินาทีให้เว็บตื่น
2. กดปุ่ม **"ตั้งค่า"** มุมขวาบนของเว็บ
3. นำ **Channel access token** จาก LINE Developers Console มาวางในช่อง "LINE Channel Access Token" แล้วกด "บันทึกการตั้งค่า"
4. ตั้งเกณฑ์เวลา เช่น "เปิดไฟเกิน 30 นาทีให้แจ้งเตือน" และ "แจ้งซ้ำทุก 30 นาที" ถ้ายังไม่ปิด

## ตั้งค่าระบบลงทะเบียนลูกค้าด้วยตัวเอง (LIFF) — วิธีหลักที่แนะนำ

วิธีนี้ให้ลูกค้ากดลิงก์เดียว แล้วผูก LINE ของตัวเองกับห้องได้เลย ไม่ต้องให้แอดมินไปคัดลอก userId ทีละคน

**สำคัญ:** ปัจจุบัน LINE ไม่ให้เพิ่ม LIFF ใน Messaging API channel โดยตรงแล้ว ต้องสร้าง **LINE Login channel** แยกขึ้นมาก่อน (ภายใต้ provider เดียวกับ Messaging API channel ของคุณ)

1. ไปที่ [LINE Developers Console](https://developers.line.biz/console/) → เลือก provider เดิมที่มี Messaging API channel ของ OA อยู่
2. กด **Create a new channel** → เลือก **LINE Login** → ตั้งชื่อ → App types เลือก **Web app** → Create
3. (แนะนำ) ในแท็บ Basic settings ของ channel ใหม่นี้ → หา **Linked bots** → Edit → เลือก Messaging API channel (OA) ของคุณ → Update
4. ไปที่แท็บ **LIFF** ของ channel ใหม่นี้ → กด **Add**
5. กรอกข้อมูล:
   - LIFF app name: ตั้งชื่อได้ตามใจ เช่น "ลงทะเบียนห้อง"
   - Size: **Full**
   - Endpoint URL: `https://โดเมนของคุณ/register.html` (โดเมนจาก Render ในขั้นที่ 3 ด้านบน)
   - Scope: ติ๊ก **profile** อย่างน้อย
6. กด Add แล้วคัดลอก **LIFF ID** (หน้าตาประมาณ `1234567890-abcdefgh`)
7. กลับมาที่แดชบอร์ด > ปุ่ม **"ตั้งค่า"** > วาง LIFF ID ในช่อง "LIFF ID" > บันทึกการตั้งค่า
8. ที่การ์ดแต่ละห้องในแดชบอร์ด จะมีปุ่ม **🔗** กดเพื่อคัดลอกลิงก์ลงทะเบียนของห้องนั้น (รูปแบบ `https://liff.line.me/{LIFF_ID}?code=101`)
9. ส่งลิงก์นั้นให้ลูกค้า (แชท, ใบนัดหมาย, หรือทำเป็น QR code ก็ได้) — เมื่อลูกค้ากดลิงก์จากในแอป LINE ระบบจะ:
   - ล็อกอินด้วย LINE ให้อัตโนมัติ
   - ดึงรหัสห้องจากลิงก์มาเติมในฟอร์มให้
   - ลูกค้ากด "ยืนยันการลงทะเบียน" ครั้งเดียว เสร็จเลย

> หมายเหตุ: รหัสห้อง (`code`) ตั้งตอนเพิ่ม/แก้ไขห้องในแดชบอร์ด ควรตั้งเป็นเลขห้องที่ลูกค้าจดจำได้ง่าย เช่น "101"

### ถ้าไม่อยากใช้ LIFF — วิธีสำรอง (กรอก userId เอง)

ยังสามารถผูก LINE userId ให้ลูกค้าด้วยมือได้เหมือนเดิม:

1. ไปที่ Messaging API channel เดิม (อันที่มี OA) → ตั้งค่า **Webhook URL** เป็น `https://โดเมนของคุณ/webhook` แล้วเปิด "Use webhook"
2. ให้ลูกค้าทักแชทอะไรก็ได้เข้ามาที่ LINE OA สักหนึ่งครั้ง
3. ที่เว็บแอป > "ตั้งค่า" > ดูหัวข้อ **"ผู้ทักแชทล่าสุด"** คัดลอก userId แล้วนำไปวางตอนเพิ่ม/แก้ไขห้อง

> หมายเหตุ: โค้ดเวอร์ชันนี้ยังไม่ได้ตรวจลายเซ็น (signature) ของ webhook เพื่อความง่ายในการเริ่มต้น
> ถ้าจะใช้งานจริงบนอินเทอร์เน็ตสาธารณะ ควรเพิ่มการตรวจสอบ `x-line-signature` ตามเอกสาร LINE
> (https://developers.line.biz/en/docs/messaging-api/receiving-messages/#verifying-signatures) ก่อน

## เชื่อมต่อเซ็นเซอร์ไฟจริง

ถ้ามีสมาร์ทปลั๊ก/เซ็นเซอร์ตรวจไฟ (เช่น ESP32, Shelly, Tasmota) ให้ตั้งค่าอุปกรณ์ยิง HTTP request มาที่:

```bash
curl -X POST https://โดเมนของคุณ/api/sensor/room-1 \
  -H "Content-Type: application/json" \
  -H "x-api-key: ค่า_SENSOR_API_KEY_ที่ตั้งไว้บน Render" \
  -d '{"status":"on"}'
```

เปลี่ยน `room-1` เป็น id ของห้องนั้น (ดู id ได้จากแถบ network ในเบราว์เซอร์ตอนเปิดแดชบอร์ด)
ส่ง `"status":"off"` เมื่อปิดไฟ

ถ้ายังไม่มีเซ็นเซอร์จริง ใช้ปุ่ม "เปิดไฟ/ปิดไฟ (จำลอง)" บนการ์ดแต่ละห้องในหน้าเว็บแทนได้เลย

## รันทดสอบในเครื่องตัวเอง (ก่อน/ระหว่างพัฒนา)

```bash
npm install
cp .env.example .env
# กรอก MONGODB_URI ใน .env ด้วย connection string จาก MongoDB Atlas (ใช้ตัวเดียวกับที่ตั้งบน Render ได้เลย)
npm start
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

ถ้าต้องการทดสอบหน้าลงทะเบียน LIFF จากเครื่องตัวเอง (ก่อน deploy ขึ้น Render) ต้องใช้ [ngrok](https://ngrok.com/) เพื่อให้ได้ URL แบบ HTTPS ชั่วคราว เพราะ LIFF ใช้ `localhost` ตรง ๆ ไม่ได้:

```bash
npm start          # รันเว็บที่ port 3000
ngrok http 3000     # จะได้ URL ชั่วคราว เช่น https://xxxx.ngrok-free.app
```

## ข้อควรระวังก่อนใช้งานจริง

- หน้าเว็บนี้**ยังไม่มีระบบล็อกอิน/สิทธิ์การเข้าใช้** ถ้าจะเปิดให้เข้าถึงจากอินเทอร์เน็ตสาธารณะ
  ควรเพิ่ม authentication ก่อน ไม่อย่างนั้นใครก็แก้ไขห้อง/ดูข้อมูลได้ (ลิงก์ Render เดารหัสยากเพราะมีตัวเลขสุ่มต่อท้าย แต่ก็ไม่ใช่การป้องกันที่แท้จริง)
- Channel access token และ MongoDB connection string เป็นข้อมูลลับ **ห้าม commit ไฟล์ `.env` ขึ้น GitHub เด็ดขาด** (มี `.gitignore` กันไว้ให้แล้ว แต่อย่าลืมเช็ก)
- แผน MongoDB Atlas free (M0) มีพื้นที่ 512MB ซึ่งเพียงพอมากสำหรับระบบขนาดนี้ (หลักร้อย-พันห้อง)
